## Chapter 1 - What I was doing vs what assessors see

### Context

I get feedback in team meetings. Gerald gives suggestions. Thijmen reviews my code. But none of it ends up in Portflow.

### Findings

| What I was doing | What assessors see |
|---|---|
| Verbal feedback in meetings | Zero feedback comments |
| Thijmen reviews my code informally | No recorded validations |
| Gerald gives suggestions | No expert responses |
| I process feedback and update code | No evidence of iteration |

To assessors, it looks like I work alone and never ask anyone for input. The work was collaborative, but the evidence says otherwise.

### Sub-conclusion

If it is not in Portflow, it did not happen. Verbal feedback is invisible to assessors.

## Chapter 2 - Concrete feedback plan

### Sprint 3 remaining weeks

| Week | Action | Who |
|------|--------|-----|
| Week 13 | Ask Thijmen to review speed camera router code | Thijmen |
| Week 13 | Ask Gerald to validate problem statement framing | Gerald |
| Week 13 | Ask Mats for 1-on-1 Progress Review prep | Mats |

### Sprint 4 plan

| When | Action |
|------|--------|
| Week 1 | Write learning goals, send to Gerald for feedback |
| Week 1 | Record Gerald's response in Portflow |
| Week 2 | First code delivery, ask teammate for review |
| Week 3 | Midpoint check with Mats or Gerald |

### How to record

1. Ask for feedback explicitly with a specific question ("Can you check if the stakeholder mapping is realistic?")
2. Record the feedback in Portflow as a comment
3. Respond to the feedback. Show what I changed.

### Sub-conclusion

The fix is simple: ask, record, respond. Every week. No exceptions.

## Conclusion

My feedback gap is a habit problem, not a technical one. I default to working silently. The plan is concrete: specific people, specific weeks, specific questions. Sprint 4 starts with learning goals sent to Gerald in week 1.
