# City sim learning group - Analysis

### Learning Question

Which code structure is most suitable for organising the smart streetlight functionality as reusable and mergeable code within one shared ESP32-S3 project for Sprint 2?

### S - Situation

In Sprint 2 of the City Sim Learning Group, I am no longer only focused on making the smart streetlight work as a separate prototype, because the first version has already been analysed, designed, realised, and evaluated in Sprint 1. In this sprint, the project moves to the next step, where the code must be organised in a way that can be combined with the work of the other team members. Gerald explained that the code of all group members must eventually be merged into one project, so that it can run on all ESP32 boards of the learning group. This means that the ESP32 boards should be treated as multifunctional City Hubs instead of boards that only run one isolated function. At this point, I do not yet clearly understand how I should structure my smart streetlight code in such a way that it becomes reusable, clear, and suitable for merging into a shared project. Because of that, I first need to analyse the problem before moving on to the design and realisation phases of Sprint 2.

### T - Task

My task in this phase is to determine how the smart streetlight code should be structured so that it can function as reusable and mergeable code within one shared ESP32-S3 project. To do that, I need to describe the context and project goal of this Sprint 2 development step, identify what reusable and mergeable code means in the context of the learning group, determine which parts of the current smart streetlight code should be placed in a separate library or module, examine how this structure can support integration with the code of other team members, and analyse how the code can be organised so that it fits the idea of multifunctional City Hubs. I also need to structure these findings in a clear analysis document.
